# MALSONSA v1.1

수집된 로그를 HOLD 전에 위험도로 검토하고, 에이전트별 관제 룰과 저장한 로그·SRC IP 위험도 탭으로 분석을 이어갈 수 있습니다. 중앙 배치는 agent의 syslog 원본과 분석 결과를 primary DB 서버에 보관하며 WAS는 메모리에서 상관분석합니다.

## 주요 변경

- 화이트 테마, 점수 구간별 검토 우선순위, 가점·관찰값·시간 차이의 근거 표시.
- 에이전트별 룰 CRUD, AND/OR 조건, 반복 횟수·시간창·묶음 기준, 저장 전 미리보기.
- 수집 로그 위험도 열: 자체 점수와 연관 로그 합계. 저장한 로그와 SRC별 건수·위험도 조회.
- 동일 데이터의 불필요한 표 재생성 방지, DB 로그 시각과 SRC 정규화 보정.
- 중앙 MariaDB raw_logs/events/analysis_results 및 HOLD·즐겨찾기·호스트·룰 저장.
- IP/앵커 디렉터리, 미시 하드 링크, Similar 튜플 TXT·위치 TXT, 인증 archive API.
- 배치 정규화·분석·export, 원본 ID 중복 정규화 방지, 전달 큐 복구 및 IP 기반 DB 인증.
- v1.1 설치 패키지·체크섬. 단일 서버 설치와 중앙 역할별 설치 도구를 함께 제공.

## 설치 범위

`install.sh`는 단일 서버 SQLite 구축용입니다. 중앙 배치는 `docs/CENTRAL_STORAGE.md`에 따라 `deploy/central/`의 DB·agent·WAS 도구를 사용합니다. 중앙 모드에 단일 서버 `install.sh --upgrade`를 적용하지 않습니다. 기존 v1.0 배포 파일은 유지합니다.

## 검증

로컬 Python 30개 중 27개 성공·실제 MariaDB 필요 3개 생략. GitHub CI에서는 실제 MariaDB 검사, SIEM 검사, 대시보드 빌드/JS 검사, 설치·업그레이드·로그 회전, 병합 정책을 검사합니다. 릴리스는 모든 job 성공 이후 게시합니다.

개발망에서는 기존 이벤트 5,188건의 ID·내용 보존, 이전 agent 전달 큐 1,797건 복구, 원본→정규화→JSON/TXT→HOLD/Similar 흐름을 확인했습니다. 정리 후 시험에서도 관련 서비스 정상과 원본/export 대기 0건을 확인했습니다. 중앙 백업을 SHA256 검증한 후 사용자 승인 범위의 과거 WAS DB·백업·수집 파일을 정리했습니다.

## 해석과 운영 한계

점수는 검토 우선순위이며 공격 확률이나 확정 판정이 아닙니다. 상관 후보는 최근 최대 5,000건, 연관 합산은 전후 60분·최대 500건입니다. SRC 위험도는 범위 내 최근 최대 20건의 최고 점수입니다. 현재 공용 보관함과 private lab TCP/HTTP 통신을 사용하며, 사용자별 인증·외부망 TLS·고가용성은 추가 설계 대상입니다.
