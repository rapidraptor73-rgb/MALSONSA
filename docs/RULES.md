# 에이전트별 관제 룰

메인 메뉴의 **관제 룰셋 추가** 또는 상관분석 상단의 **관제 룰셋**을 엽니다.
에이전트는 호스트 관리에 등록된 관제 호스트입니다. 적용 대상은 정규화된 로그의
`host_ip`이며 출발지·목적지 IP로 에이전트를 추측하지 않습니다.

1. 호스트 관리에서 에이전트를 등록합니다.
2. 관제 룰셋에서 에이전트, 룰 이름, 추정 공격명, 부여 점수, 판단 이유를 입력합니다.
3. 메시지·프로그램·이벤트·SRC·DST·사용자·MITRE 조건을 추가합니다. 포함/정확히 일치,
   대소문자 무시, AND/OR 조합을 지원합니다. 정규식이나 실행 코드는 사용하지 않습니다.
4. 반복 조건이 필요하면 최소 횟수, 시간창(초), SRC/DST/사용자/프로그램/에이전트 전체 중
   묶음 기준을 선택합니다. 단일 로그는 최소 횟수 1로 설정합니다.
5. 상관분석 상세 보기에서 LOG ID를 확인한 뒤 저장 전 테스트를 실행합니다.
6. 저장 후 상관분석을 새로고침합니다. 추정 공격명·점수·판단 이유·관찰값·반복 횟수가 표시됩니다.

**SSH 반복 실패 예시** 버튼은 `AUTH_FAILURE`이면서 메시지에 `failed password`를 포함하는
로그가 같은 에이전트의 같은 SRC에서 300초 내 5회 이상 발생하면 120점을 부여하는
예시를 채웁니다. 실제 프로그램과 로그 형식에 맞게 조건을 조정하고 저장하세요.
여러 공격을 감지하려면 에이전트별로 별도의 룰을 등록합니다. 에이전트당 최대 100개,
룰당 최대 8개 조건과 1~200점을 지원합니다.

탐지 점수는 일치한 활성 룰 점수의 합계입니다. Critical ≥120, High ≥90, Medium ≥60,
Low <60으로 표시합니다. 공격 가설을 검토하는 우선순위이며 확정 판정이나 확률이 아닙니다.
탐지 점수와 기존 Similar의 개별 상관점수는 별도로 표시합니다. 수집 로그의 새 종합 검토 점수는
아래 별도 정책에 따라 자체 점수와 연관 상관점수 합계를 결합합니다.
중복 조건의 여러 룰은 각각 가산되므로 중복 룰 등록에 유의하세요.

반복 횟수는 해당 이벤트 발생 시각까지의 시간창에서 조건을 만족하는 저장 이벤트를 셉니다.
발생 시각이 같으면 해당 이벤트 ID 이하만 포함합니다. 이후 이벤트와 다른 에이전트·묶음의
로그는 포함하지 않습니다. SRC 등의 묶음 값이 없는 로그는 반복 룰에 일치하지 않습니다.
최소 횟수에 도달한 이벤트부터 점수가 표시되고 앞선 이벤트에 소급해 횟수를 채우지 않습니다.

룰은 SQLite `detection_rules`에 저장되며 서비스 재시작·DB 백업·업그레이드 시 보존됩니다.
현재 룰로 조회 시 재평가하므로 기존 이벤트도 새 조건에 따라 표시됩니다. 룰 변경 전 판정의
불변 이력이나 별도 알림 전송은 제공하지 않습니다. 룰 또는 에이전트를 비활성화하면
다음 조회부터 해당 점수가 제외됩니다. 연결된 룰이 있는 에이전트는 룰을 삭제하거나
다른 에이전트로 이동한 후 삭제할 수 있습니다.

API: `GET/POST /api/rules`, `PATCH/DELETE /api/rules/<id>`, `POST /api/rules/preview`.
미리보기는 `{ "rule": { ... }, "event_id": 123 }`을 받으며 룰을 저장하지 않습니다.
v1.0 배포 파일과 main은 기존 릴리스 상태로 유지됩니다. 이 기능이 포함된 소스 패키지는 develop에서
`python scripts/build_release.py`로 생성할 수 있습니다.

## 수집 로그의 사전 위험도

수집 로그는 `GET /api/events?include_risk=1` 응답의 `risk_summary`로 상세 보기/Hold 이전에도 검토 우선순위를 표시합니다. Hold 상태는 변경하지 않습니다.

- 자체 점수 = 의심 이벤트 유형 20점 + 현재 일치 에이전트 룰 점수. 일반 유형의 기본 점수는 0점입니다.
- 연관 합계 = 같은 호스트, 같은 SRC 또는 사용자, 전후 60분, Similar 점수 60점 이상의 로그 상관점수 합계. 양쪽 중 하나는 의심 이벤트 유형이어야 합니다. 목적지만 같은 일반 로그는 합산하지 않습니다.
- 종합 점수 = 자체 점수 + 연관 합계. Critical 120 이상, High 90–119, Medium 60–89, Low 0–59로 표시합니다. 반복 로그 수에 따라 커지는 검토 지표이며 공격 확률은 아닙니다.
- 최근 수집 5,000건을 후보로 사용하고 높은 상관점수순 최대 500건을 합산합니다. 사용한 후보 수·상한·연관 수를 화면에 표시합니다. 목록 검색/조회 기간/호스트 탭은 표시만 제한하며 계산 기준을 바꾸지 않습니다.
- 시각이 없거나 잘못된 로그는 연관 계산에서 제외하고 자체 점수만 표시합니다. 현재 데이터 기준으로 과거 로그도 재평가되므로 이후에 들어온 연관 로그가 이전 로그의 종합 점수에 영향을 줄 수 있습니다.
- 종합 필터는 합계 위험도, "룰 탐지 로그만"은 실제 룰 일치 여부를 사용합니다. 아래 Similar 상세 화면의 점수는 개별 두 로그의 연관성으로 별도 표시합니다.

## 저장한 로그와 SRC IP 위험도 탭

수집 로그의 `☆ 저장`을 누르면 `★ 저장됨`으로 바뀌고 **저장한 로그** 탭에서 다시 볼 수 있습니다.
HOLD와는 독립적이며 저장 해제는 원본 이벤트를 삭제하지 않습니다. `soc_bookmarks`에 원문/정규화
이벤트의 사본과 저장 시각을 기록하므로 재접속·서비스 재시작 이후에도 유지됩니다. 원본이 없어진
경우 사본은 표시하지만 원본에 대한 상세 분석은 비활성화합니다. 점수는 현재 룰/연관 로그로 재평가합니다.
로그인 계정 구분이 없는 현재 SIEM에서는 설치 단위의 공용 보관함이며 사용자별 비공개 보관함은 아닙니다.
저장 목록은 기간·위험도 필터와 무관하며 호스트/검색을 적용해 50건씩 페이지로 조회합니다.

**SRC IP 위험도**는 선택한 기간·호스트에 해당하는 DB 전체의 SRC별 건수를 내림차순으로 표시합니다.
SRC가 없는 이벤트는 목록에서 제외합니다. IP 위험도는 각 IP의 해당 범위에서 최근 수집 최대 20건의
종합 점수 중 최댓값이며, 이미 같은 연관 활동이 포함된 로그 점수를 다시 모두 합산하지 않습니다.
따라서 이전 전체 이력의 최고 위험도를 보장하는 통계는 아닙니다. 수집 건수·의심 유형 건수·호스트 수는
전체 선택 범위, 분석 건수·Critical 건수·추정 공격은 이 20건 분석 범위입니다. 개별 이벤트의 연관
점수는 기존 최신 5,000건 후보/전후 60분 정책을 유지하여 통계 기간 밖의 연관 로그도 반영될 수 있습니다.
`이 IP 로그 보기`는 선택한 SRC의 로그를 서버에서 조회한 뒤 기존 상세 분석으로 연결합니다.

API: `POST/DELETE /api/bookmarks/<id>`, `GET /api/bookmarks?page=1&per_page=50&host_ip=...&field=message&q=...`,
`GET /api/source-ips?seconds=300&page=1&per_page=50&host_ip=...&q=...`. SRC 조회 기간은
0(전체), 300, 900, 3600, 21600, 86400초를 지원합니다. main/릴리스 게시는 별도 사용자 요청이 필요합니다.
